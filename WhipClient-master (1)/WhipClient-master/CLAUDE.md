- **WhipBin**: Mapping pipeline at `C:/Users/Java/Desktop/whip/WhipBin` - generates binary mappings from JSON
- **MCP Source**: Decompiled Minecraft reference at `C:/Users/Java/Desktop/mcp908/src/minecraft/net/minecraft/`

## Architecture

### JNI Bytecode Hooking System

WhipClient uses **bytecode transformation** to hook into Minecraft methods (not native code injection):

- **Instrumentation**: Java agent-style bytecode rewriting via JNI `retransformClasses`
- **Hook Registry**: `includes/hook/transformer_registry.hpp` manages hook transformers
- **Dispatcher**: Pre-generated bytecode templates inject method calls back to C++ via JNI
- **Implementation**: Each hook in `src/hook/sub/` implements the actual C++ logic

**Key files:**
- `src/hook/instrumentation.cpp` - JVMTI capabilities and class retransformation
- `src/hook/classfile.cpp` - Bytecode parsing and modification
- `src/hook/dispatcher.cpp` - JNI method dispatcher (receives callbacks from Java)
- `includes/hook/embedded_transformer.hpp` - Embedded bytecode templates

**Adding a new hook:**
1. Create `includes/hook/sub/MyHook.h` and `src/hook/sub/MyHook.cpp`
2. Implement the hook logic with JNI method signature
3. Register in `transformer_registry.hpp`
4. Update bytecode templates if needed (use `tools/compile_and_extract.bat`)

### Module System

All features are implemented as modules inheriting from `BaseModule<Derived, Type, Category>`:

- **Module Types**: `ModuleType` enum (e.g., BRIDGE_ASSIST, BACKTRACK, AUTO_TOOL)
- **Categories**: `CategoryType` (COMBAT, MOVEMENT, VISUAL, MISC, BACKEND, etc.)
- **Module Base**: `includes/module/base/BaseModule.h` provides singleton pattern and lifecycle (onEnable/onDisable)
- **Specialized Bases**:
  - `ListenedBaseModule` - Auto-subscribes to EventBus
  - `BindBaseModule` - Adds keybind support
  - `Render2dBaseModule` - 2D rendering hooks
  - `Render3dBaseModule` - 3D world rendering

**Module location pattern:**
- Headers: `includes/module/impl/{category}/{ModuleName}.h`
- Implementation: `src/module/impl/{category}/{ModuleName}.cpp`

### Event System

Event-driven architecture using an observer pattern:

- **EventBus**: `includes/bus/EventBus.h` - Central event dispatcher with priority-based listeners
- **Events**: All in `includes/event/sub/` (e.g., `OnTickEvent`, `MouseLeftClickEvent`)
- **Subscription**: Modules subscribe via `EventBus::subscribe<EventType>(this, callback, priority)`
- **Cancellable**: Events can inherit `Cancellable` to allow early termination

### Authentication Flow

WhipClient performs a two-phase auth on startup:

**Phase 1** (WhipLoader):
1. Connect to WhipServer via WhipNexus
2. Authenticate with downloadId or HWID
3. Select product 0 (auto-selected, matches loader)
4. Download and inject WhipClient.dll

**Phase 2** (WhipClient DLL, in `ClientMain::mainThreadProc`):
1. Initialize WhipNexus and syscall manager
2. Detect Minecraft version (v1_7_10 or v1_8_9)
3. Connect to server and authenticate with HWID
4. Request and load binary mappings (.wbin files)
5. Setup JNI mappings for detected version
6. Register bytecode hooks
7. Enter main loop

**Key auth files:**
- `includes/auth/service/WhipAuthService.h` - Main auth service with heartbeat
- `includes/auth/session/SessionManager.h` - Session token management
- `includes/auth/ipc/LoaderIpcClient.h` - IPC with WhipLoader (when `LOADER_IPC` defined)
- `src/auth/version/VersionDetector.cpp` - Minecraft version detection

### Mapping Quick Reference

Each mapping has:
- **name**: Actual deobfuscated name from MCP (e.g., "posX", "attackTargetEntityWithCurrentItem")
- **sig**: JNI type signature (e.g., "D" for double, "(Lnet/minecraft/entity/Entity;)V" for method)
- **isStatic**: 1 if static, 0 if instance
- **isGlobal**: Usually 0 (rare use case for globally accessible fields)

**Common JNI Signatures**:
- `V` = void
- `Z` = boolean
- `I` = int
- `F` = float
- `D` = double
- `Lnet/minecraft/entity/Entity;` = Entity object (note the semicolon!)
- `(IZ)V` = method taking int and boolean, returning void
- `()Lnet/minecraft/util/Vec3;` = method returning Vec3, no parameters

### JNI Wrappers

All Minecraft classes have C++ wrappers in `includes/wrapper/minecraft/` that use the mapping system to access obfuscated Java code.

**Wrapper Structure**:
- Headers: `includes/wrapper/minecraft/{category}/{ClassName}MC.h`
- Implementation: `src/wrapper/minecraft/{category}/{ClassName}MC.cpp`
- Naming: Java class name + "MC" suffix (e.g., `Entity` → `EntityMC`)

**How Wrappers Use Mappings**:

```cpp
// Example: EntityMC wrapper accessing Entity.posX field
// File: includes/wrapper/minecraft/entity/EntityMC.h

class EntityMC {
public:
    // Get entity's X position using "posX" mapping
    static double getPosX(JNIEnv* env, jobject entity) {
        // mappings->getField("posX") retrieves the jfieldID from loaded .wbin
        auto posXField = mappings->getField("posX");
        return env->GetDoubleField(entity, posXField);
    }

    // Call entity's rayTrace method using "rayTrace" mapping
    static jobject rayTrace(JNIEnv* env, jobject entity, double distance, float partialTicks) {
        // mappings->getMethod("rayTrace") retrieves the jmethodID
        auto rayTraceMethod = mappings->getMethod("rayTrace");
        return env->CallObjectMethod(entity, rayTraceMethod, distance, partialTicks);
    }
};
```

**Key Points**:
- Mapping IDs (like "posX", "rayTrace") must match entries in `WhipBin/mappings/{version}/lunar.json`
- The `mappings` global object is initialized during `ClientMain::setupMappings()`
- Field access: `GetXXXField()` / `SetXXXField()` for fields
- Method calls: `CallXXXMethod()` / `CallStaticXXXMethod()` for methods

- **Build modes** set via `WHIP_BUILD_MODE`:

### Troubleshooting the Workflow

**Problem**: "Mapping 'isSprinting' not found"
- **Solution**: .wbin file not loaded. Check VPS deployment, restart WhipServer, check client logs

**Problem**: JVM crash when calling method
- **Solution**: Wrong signature. Re-verify in MCP source, check JNI signature conversion

**Problem**: Method works in 1.8.9 but not 1.7.10
- **Solution**: Verify method exists in both MCP versions. If different, adjust signatures per version.

**Problem**: Null pointer when calling method
- **Solution**: Ensure entity object is valid before calling. Add null checks in wrapper.
